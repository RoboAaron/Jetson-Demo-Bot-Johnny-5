# [4-8] PID State Reset on Safety Transitions + PID Logic Validation

**Parent Tasks**: [Tasks for PBI 4](./tasks.md)

## Description
Fix a latent DC-bias bug in the `PID_v1` library's `Initialize()` that
causes `balancePID`, `velocityPID`, and `yawPID` to latch a stale
non-zero `outputSum` any time they transition `MANUAL → AUTOMATIC`.
With `Ki = 0.0` and `P_ON_E` (default), `outputSum` is never updated
inside `Compute()` — it acts as a permanent DC offset applied to every
output until the next mode transition. Every IMU dropout, safety
cutoff, or power cycle that coincides with a saturated output leaves
the controller with a several-Amp constant bias that **does not** come
from instantaneous error and **does not** decay.

Also audit the broader balance-PID data flow (sign convention, filter
freshness, output clamping, input-pointer staleness) and add enough
telemetry to the stream that the next suspicious behavior can be
diagnosed without a library dive.

### Evidence that this bug is real (not theoretical)
1. **GUI screenshot, 2026-04-16 22:46**: bot on stand, `Roll=-0.61°`,
   `Setpoint=-0.60°`, `Kp=1.5`, `Ki=0.0`, `Kd=0.030` → expected
   `RollOut ≈ Kp · err = 1.5 · (-0.01) = -0.015 A`. Observed
   `RollOut ≈ +2.00 A` (pinned at `maxCurrent` for >10 minutes after the
   last IMU dropout).
2. **Library source** at `~/Arduino/libraries/PID/PID_v1.cpp` lines
   58–95 (`Compute`) and 189–195 (`Initialize`): with `Ki=0` and
   `P_ON_E`, `outputSum` is only ever written by `Initialize()` and
   `SetOutputLimits()` clamping. `SetMode(AUTOMATIC)` calls
   `Initialize()` unconditionally, snapshotting `*myOutput` into
   `outputSum`.
3. **Firmware call pattern**: `runAngleControlISR()` at lines 318–333
   toggles `SetMode(MANUAL)` on `!imuWorking || safetyCutoffActive`
   and `SetMode(AUTOMATIC)` on recovery, but only zeros the
   `volatile float motorCurrent`, never the `double pidMotorCurrent`
   that the PID writes through. So whatever saturated value the PID
   produced just before the cutoff is the value `Initialize()`
   latches on re-arm.
4. **Retrospective fit** to earlier log
   `robot_log_20260415_222218.txt`: in that session, quiet-balance
   `RollOut` was consistently smaller than `Kp · err` in one direction
   and larger in the other — exactly what a fixed `outputSum` bias
   added to a symmetric error would produce.

## Requirements
1. **R1 — Bumpless re-arm helper per PID**: Introduce
   `rearmBalancePID()`, `rearmVelocityPID()`, `rearmYawPID()` static
   inline helpers that (a) zero the PID's output double, (b) snap the
   PID's input double to the current live input so the first
   `Compute()` post-arm sees `dInput = 0`, (c) set the setpoint double
   to the current live setpoint, and (d) call
   `pid.SetMode(AUTOMATIC)`. Every existing `SetMode(AUTOMATIC)` call
   on these three PIDs is replaced with the helper.
2. **R2 — Zero on every cutoff, not just the output float**: When the
   ISR or main-loop safety paths set `motorCurrent = 0.0f`, they MUST
   also zero `pidMotorCurrent` (and the velocity/yaw counterparts).
   This belt-and-braces guarantees that even if the PID is paused in
   MANUAL without a subsequent AUTOMATIC transition, the output
   pointer it reads on next `Initialize()` is clean.
3. **R3 — Setup-time initialization is clean**: The `setup()` call to
   `balancePID.SetMode(AUTOMATIC)` (line 555) uses the helper so the
   first-ever `Initialize()` also sees zeros.
4. **R4 — `angleInput` visible in the stream**: The `R:...` stream
   line gains one additional field (`AI:<filtered>`) so filter vs
   raw-roll divergence is inspectable without a reflash. Put it after
   the existing `R:`, `P:`, `Y:` block. The `GAINS:` line is not
   touched.
5. **R5 — Sign-convention audit documented**: A short
   `docs/delivery/4/PID_LOGIC_AUDIT.md` captures the walk-through of
   all three PIDs' DIRECT/REVERSE choices, input/output/setpoint
   pointer hookup, `outputSum` reachability, clamp behavior, and
   filter freshness. Not code; just a one-time reference so future
   sessions don't re-derive it.
6. **R6 — No grepable references to the old anti-pattern**:
   `SetMode(AUTOMATIC)` on `balancePID`, `velocityPID`, or `yawPID`
   only appears inside the three helpers. Enforced by grep in the
   verification step.
7. **R7 — No behavioral regression at zero error on bench**: After
   a power cycle, holding the bot on the stand at `|roll − setpoint|
   < 0.1°` for ≥ 10 seconds, observed `RollOut` stays within ±0.15 A
   (i.e., dominated by dither and measurement noise, not a latched
   bias).

## Implementation Plan
1. **Read the three PID constructor lines** and confirm each one's
   `{input, output, setpoint}` pointer triple. Verified from file:
   - `balancePID`: `&pidAngleInput, &pidMotorCurrent, &pidAngleSetpoint`
   - `velocityPID`: `&velocityInput, &angleSetpointFromVel, &velocitySetpoint`
   - `yawPID`: `&yawInput, &yawOutput, &yawSetpoint`
2. **Add three `static inline` helpers** near the PID declarations
   (line ~135), each a literal four-line body. Form for balance:
   ```cpp
   static inline void rearmBalancePID() {
     pidMotorCurrent = 0.0;
     pidAngleInput = angleInput;
     pidAngleSetpoint = angleSetpoint;
     balancePID.SetMode(AUTOMATIC);
   }
   ```
   Analogous for velocity and yaw.
3. **Replace `balancePID.SetMode(AUTOMATIC)` call sites** with
   `rearmBalancePID()`. Per current grep, these are at lines 331
   (ISR unfreeze) and 555 (setup). Same for velocity PID at lines
   ~942, ~999, ~1169, ~561. Same for yaw PID at lines ~1000, ~571.
4. **Belt-and-braces output-zero on cutoff**: In
   `runAngleControlISR()`'s cutoff branch (lines 318–328), after
   `motorCurrent = 0.0f`, add:
   ```cpp
   pidMotorCurrent = 0.0;  // ensure next rearm() sees a clean state
   ```
   Matching pattern in any other safety path that currently only
   zeros `motorCurrent` without touching `pidMotorCurrent`. Check for
   all sites setting `motorCurrent = 0.0f` and add the double-reset.
5. **Extend the stream line**: modify `Serial.printf` at lines
   ~1070–1073 to append `,AI:%.2f` and pass `angleInput` as the final
   argument. Document in the file header comment block.
6. **Write `docs/delivery/4/PID_LOGIC_AUDIT.md`**: a one-page
   reference. Contents:
   - `balancePID`: inputs/outputs, DIRECT rationale, sign check against
     observed motor command signs, output clamp, `outputSum`
     reachability (only via helper).
   - `velocityPID`: REVERSE rationale (already documented in
     comments), clamp, deadband thrashing fix reference from 4-2.
   - `yawPID`: disabled-by-default note; same clean-rearm pattern.
   - A short "anti-windup is not the issue here; state-latching
     was" section explaining why `Ki=0` bot-sessions were producing
     integrator-like behavior despite no integrator.
7. **Grep verification**: after all edits,
   `rg 'balancePID\.SetMode\(AUTOMATIC\)|velocityPID\.SetMode\(AUTOMATIC\)|yawPID\.SetMode\(AUTOMATIC\)'`
   returns exactly three lines — one inside each helper.
8. **ReadLints** over the modified files.
