# [4-3] Optimize PID Tuning for Stability

## Description
Systematically tune angle and velocity PID gains so that balance is stable (single-loop baseline restored) and the velocity loop can be re-enabled without breaking balance. Aligns with BALANCE_CODE_REVIEW Phase 0–1 and TUNING_RECOMMENDATIONS.md.

## Status History
- 2026-02: Created; content aligned with balance code review and existing tuning docs.

## Requirements
1. **Phase 0 (firmware)**: Rate-limit VESC writes; increase velocity filter alpha; add PID reset on safety cutoff (see BALANCE_REVIEW_ACTIONS.md).
2. **Gain verification**: Load EEPROM ('g'); verify angle/velocity gains match documented baseline or TUNING_RECOMMENDATIONS; correct velocity/motor signs per VESC.
3. **Tuning sequence**: Angle loop first (setpoint, Kp, Kd, Ki), then velocity loop (Kp_vel, Ki_vel) with setpoint = 0 until stable.
4. **Derivative-on-measurement**: Confirm PID_v1 uses derivative-on-measurement to avoid derivative kick at higher Kd (review CRITICAL-5).
5. **Smooth stiction** (optional): Replace hard stiction jump with smooth mapping to reduce limit-cycle chattering (review MAJOR-2).

## Implementation Plan
1. Complete Phase 0 fixes from BALANCE_CODE_REVIEW (rate-limit writes, filter alpha, PID reset on cutoff).
2. Use log_evaluator.py on stand/floor logs to check VEL SIGN MISMATCH and roll/error stats.
3. Tune per teensy_balance_cascaded/TUNING_RECOMMENDATIONS.md (signs → setpoint → angle gains → velocity Ki).
4. Verify PID library derivative behavior; document in task or firmware comment.
5. Optionally implement smooth stiction compensation and re-test.

## Test Plan
1. Stand test: velocity setpoint 0; confirm no VEL SIGN MISMATCH (or fix sign); confirm stable roll around setpoint.
2. Floor test: balance holds 30+ s; recovery from small push without overshoot.
3. Velocity test: small velocity setpoint; robot moves without losing balance.
4. Run log_evaluator on each run; track mismatch count and roll/error stats.

## Verification
- Angle and velocity signs match VESC configuration.
- No sustained VEL SIGN MISMATCH in logs when wheels moving.
- Balance stable with velocity setpoint 0; velocity loop can be engaged without breaking balance.
- Gains saved to EEPROM and documented.
